# WFRP4e Paperdoll - контекст для Claude Code

Модуль Foundry VTT (V13/V14) для системы WFRP4e (9.x): окно снаряжения в стиле WoW - «куколка» со слотами,
сумки, статы, лента эффектов, броски, прокачка. Автор - Михаил (rain2rock). Модуль продаётся: ядро платное (~$5),
каждое дополнение платное отдельно. Ядро обязано работать без любого дополнения.

## Как общаться

- Русский язык, дружелюбно, «бро», мужской род. Кратко. Перед работой уточнять недостающее.
- Только дефис «-», никогда длинное тире «—». Кавычки русские «...».
- Сначала показать результат (скриншот мока), если просят «покажи».

## Гит - строгие правила

- Ничего не коммитить и не пушить, пока Михаил не скажет «заливай» (или «отправляй в гит»).
- Не копить коммиты по одному: по «заливай» - ВСЁ одним коммитом.
- Сообщение коммита максимально короткое (`v0.41.0: <что>`), минимум токенов на гит.
- Перед пушем поднять версию в `module.json` (пуш в main с новой версией запускает релиз).
- Никогда не коммитить платные иконки wfrp4e-core и Foundry, `tools/snapshot*.json`.
  Свою графику (`assets/icons`, `assets/ui`) - можно.

## Релиз

`.github/workflows/release.yml`: при пуше в main с изменённым `module.json` создаётся релиз `vX.Y.Z`:
- ядро: `module.json` + `module.zip`;
- каждое дополнение из `addons/<id>`: `wfrp4e-paperdoll-<id>.json` + `.zip`, версия = версия ядра (проставляет jq).

Manifest URL ядра: `https://github.com/rain2rock/wfrp4e-paperdoll/releases/latest/download/module.json`,
дополнений: `.../releases/latest/download/wfrp4e-paperdoll-<id>.json`.

## Структура

- `scripts/paperdoll-app.js` - ядро (~4000 строк): `PaperdollApp` (ApplicationV2 + Handlebars), `PaperdollTooltip`,
  утилиты, реестр дополнений `ADDONS`, `PD_UTIL`, `PD_API`, опции `PD_OPTIONS`.
  Звуки синтезируются через Web Audio, без файлов: `playCoinSound(gain)` - монеты, `playGearSound("equip"|"unequip"|"move")` -
  надеть / снять / переложить. Оба слушают опцию `sounds` и громкость интерфейса Foundry, доступны дополнениям через `PD_UTIL`.
  Общее для ядра и дополнений (всё в `PD_UTIL`, чтобы логика не двоилась): `L`/`F` - локализация (объявлены на уровне модуля,
  в функциях заново не создавать), `COIN_VALUE`/`actorCoins`/`moneyPennies`/`formatMoney`/`changeActorMoney` - деньги,
  `woundsTier` - тир ран, `confirmRemoveEffect` - диалог снятия, `effectEntry(effect, actor, {editable})` - запись ленты эффектов
  (перенесённую с предмета пассивку возвращает как `null` - её нельзя снимать из ленты).
- `scripts/main.js` - init: настройки (все `config:false`), меню настроек, `Hooks.callAll("wfrp4e-paperdoll.init", PD_API)`, клавиша.
- `scripts/settings-menu.js` - окно настроек по вкладкам: категории ядра + вкладка на каждое дополнение.
- `scripts/translate.js`, `scripts/glossary-ru.js` - перевод терминов и описаний. `icon-index.js`, `icon-rules.js` - подбор иконок.
- `templates/paperdoll.hbs`, `styles/paperdoll.css`, `lang/ru.json`, `lang/en.json`.
- `addons/<id>/` - дополнения. СЕЙЧАС ВСЁ ЕДИНЫМ ПАКЕТОМ: их скрипты, стили и языки перечислены прямо
  в `module.json` ядра, ставить и включать надо только один модуль. Манифесты `addons/*/module.json`
  сохранены для будущего разделения и в `module.zip` не попадают (workflow их исключает).
  Чтобы снова разделить - убрать `addons/*` из `esmodules`/`styles`/`languages` ядра.
  Манифест дополнения генерирует `python3 tools/make-addon-manifest.py <id> "<title>" "<desc>" [socket]`.
- `"socket": true` теперь у ЯДРА: передача вещей шлёт сокет в неймспейсе ядра (`module.wfrp4e-paperdoll`),
  а право объявлялось у дополнения - из-за этого передача через ГМ, скорее всего, не работала вовсе.

## Дополнения

| id | Что | Хуки/методы |
|---|---|---|
| magic | вкладка «Магия», каст по клику, штраф брони к касту, разбор дальности и выбор целей (`scripts/targeting.js`) | tabs, statSets, restrictions, глобал `__PD_MAGIC_TARGETING__` |
| injuries | травмы конечностей, протезы | mixin `_limbState/_injuryLimb/_maimView`, `prostheticKind`, restrictions |
| mutations | мутации в ленте эффектов, лишние руки/головы | mixin `_extraSlots`, effects, effectClick |
| progression | «+» за опыт, дерево, вехи карьеры, покупка талантов | mixin `_advInfo/_advance/_advanceTree/_milestones/_careerCategory/_talentOffers/_buyTalent`, onRender |
| party | передача вещей на токен, общий сундук, окно группы для ГМ (раны/удача/броня/золото/эффекты кликабельно как в карточке, карточки или таблица, казна группы), «Начало сессии», «+» у ленты - поиск и выдача состояния, а также мутации и травмы из компендиумов, если стоят дополнения mutations / injuries | bagToolbar, onRender, externalDrop, socket, keybinding `openGroup` (ГМ, по умолчанию G), `api.openStash`, `api.openGroup` |

### API дополнений

Скрипт дополнения - IIFE:
```js
if (globalThis.__PD_MOCK__) register(globalThis.__PD_API__);
else Hooks.once("wfrp4e-paperdoll.init", register);
```
- `api.registerAddon({ id, title, intro, icon, settings, tabs, ...hooks })` - регистрирует и настройки (в неймспейсе ядра,
  `config:false`; boolean-дефолты попадают в `PD_OPTIONS`). Настройка: `{ key, default, type?, scope?, choices?, actorSelect? }`.
- `api.mixin(Class)` - копирует методы класса в `PaperdollApp.prototype` (переопределяет дефолты ядра).
- `api.util` = `PD_UTIL` (esc, safe, T, norm, option, itemImg, uiArt, LIMB_LOCS, EXTRA_HANDS, ...).
- Хуки: `tabs[{id,label,icon,visible(app),render(app),onRender(app,el)}]`, `statSets(app, sets, {row, profile})`,
  `restrictions(app, item, slot, out{forbid,warn,score}, profile)`, `bagToolbar(app) -> html`, `onRender(app, root)`,
  `externalDrop(app, item, data) -> bool`, `effects(app, out)`, `effectClick(app, entry, ev) -> bool`.
- В ядре дефолты «без дополнения»: конечности целы, лишних слотов нет, `_advInfo()` = null, нет дерева и вех.
- Ассеты ядра из CSS дополнения: `url("../../wfrp4e-paperdoll/assets/...")`.

## Мок и проверки

Мок - настоящий код модуля поверх заглушки Foundry (`tools/mock-runtime.js`), один html-файл.
```bash
npm install
npm run mock                                              # docs/paperdoll-mock.html
node tools/build-mock.mjs --cast --out mock-all.html      # переключатель персонажей (Хьюго, Гюнтер, Эльза)
node tools/build-mock.mjs --cast --addons none --out mock-core.html   # только ядро; all | magic,party
tools/qa/run-all.sh                                       # всё сразу: с дополнениями и без
```
Проверки в `tools/qa/` (нужен playwright: `npm i -D playwright && npx playwright install chromium`):
- `qa.mjs <mock>` - слоты, фильтры, сортировка, перетаскивание (~100 проверок, все должны быть PASS);
- `addchk.mjs <mock>` - вкладки, травмы, лишние слоты, прокачка по персонажам;
- `mutchk.mjs`, `progchk.mjs` - мутации и прокачка; `partychk.mjs` - окно группы и «Начало сессии»;
  `sfxchk.mjs` - звуки (надеть/снять/переложить/монеты) через перехват Web Audio; `magicchk.mjs` - разбор дальностей и выбор целей;
  `smoke.mjs` - импорт main.js и окно настроек.
Тестовые персонажи (`tools/mock-data.mjs`): «Хьюго» - основной, для общих проверок; «Гюнтер» (--cast) - минимум вещей и много свободного опыта специально для прокачки/покупки талантов;
«Сестра Эльза» (--cast) - жрица с благословениями разных дальностей, для проверки выбора целей.
Скриншоты для себя - через playwright (`page.screenshot`), Михаил смотрит мок в браузере.

## Правила игры (WFRP4e), которые уже зашиты

- Отдых: Стойкость (Endurance) +20 раз в день, лечит БВ + УУ ран, день полного покоя - ещё +БВ.
- Талант: 100 опыта + 100 за каждый взятый уровень, только таланты текущей ступени карьеры.
- Без оружия: СБ+0, Undamaging, навык Brawling. Resilience = «Упорство», Endurance = «Стойкость».
- Скрытность и наблюдательность - не защита: показываются в «Тело»/«Разум» и только если не ноль.
- Полосы дальности стрелкового: в упор (до 1/10 дальности) +20, короткая (1/2) +10, обычная (1) 0,
  длинная (x2) -10, запредельная (x3) -30, дальше - выстрела нет. Таблица - `RANGE_BANDS` в ядре,
  цифры взяты из книги; если в твоей редакции иначе - правится только она.

## Отложено / идеи

- Иконки «по названию» (папка by-name) - ждут иконки от Михаила из Figma.
- Полоса нагрузки шире и правки полосы удачи - одной правкой, когда будут иконки.
- Диагностический макрос для настоящего Foundry: по магии уже есть (`tools/diagnose-magic.js`), по остальному - нет.
- Окно настроек, сокеты, сундук, dropCanvasData проверены только в моке - проверить в живом Foundry.
- Окно группы: кнопка «+» зовёт `actor.addCondition(key, value)` - метод в живой системе ЕСТЬ (проверено),
  запасной путь с созданием ActiveEffect остаётся на случай других версий. Сигнатура (принимает ли второй аргумент) не проверена.
- У актёра есть и `applyDamage`, `applyEffect`, `setupWeapon` - если понадобится, часть расчётов можно отдать системе.
- Благословения и чудеса НЕСУТ свои ActiveEffect (`transfer: false`, срабатывают на цели), значит бафф после каста
  вешает система. Наш мок этого не делает - там каст только кидает кубы и пишет в чат.
- Мутации и травмы в меню «+» берутся из компендиумов предметов по `type`. В моке компендиум поддельный (`tools/mock-runtime.js`).
  В мире Михаила их достаточно: мутаций 391, травм 27, болезней 31, критов 109 - меню будет непустым.
- Состояний в `game.wfrp4e.config.conditions` пятнадцать: к нашим четырнадцати добавилось `defeated`.
- Сокеты: Foundry не подписывает module-сокеты, поэтому ГМ проверяет права по `userId` из payload (его теоретически можно подделать).
  Полная защита невозможна в принципе - рассчитываем на доверенный состав стола.
- Дополнение `party` разрослось (~800 строк, три фичи). Разбить на файлы мешает сборка: в Foundry скрипты дополнения -
  отдельные ES-модули без общей области видимости, а мок их просто склеивает. Нужен либо общий неймспейс, либо сборка с импортами.
- Идеи: смена карьеры, наборы снаряжения.

## Токены и дистанции (ядро)

`tokenOf`, `distanceBetween`, `tokensInRange` живут в ядре и экспортируются через `PD_UTIL`: ими пользуются
и оружие, и магия, чтобы дистанция считалась одним кодом. Дальность меряется через `canvas.grid.measurePath`
(Foundry v12+), запасной путь - `measureDistance`, потом евклид по клеткам.

Оружие: `weaponRangeYards` берёт посчитанную системой `Range` (как и `Damage`), `weaponRangeBand(item, distance)`
говорит полосу и модификатор. В подсказке оружия строка «До цели» появляется, только когда игрок выбрал цель
(`game.user.targets`), и показывает дистанцию, полосу и модификатор.

Подсказка оружия подстраивается под выбранную цель (`targetedAttack` в ядре):
- цели нет - базовый шанс попасть и базовый урон, как раньше;
- цель выбрана - «Шанс по цели» (база + модификатор полосы дальности) и «Урон по цели»
  (урон с бонусами талантов минус Бонус Выносливости и броня корпуса цели, не ниже нуля).
Итоговое число видно всегда, а из чего оно сложилось - только при включённой опции «Подробные статы» (`detailedStats`).
Часть тела до броска неизвестна, поэтому берём корпус - он выпадает чаще прочих; это указано в разборе.
Уровни успеха в урон не входят: они известны только после броска.

- Урон оружия и так считает система (`system.Damage`), модуль лишь добавляет бонусы талантов - см. `_weaponDamage`.
- Учитывает ли сама система полосы дальности при броске - НЕ проверено. Если да, наш показ останется
  справочным, дублировать модификатор в бросок не нужно.

## Магия: выбор целей (в работе)

Бросок, УУ, ЧС и применение эффектов делает САМА система (`actor.setupCast` / `actor.setupPrayer`, см. `addons/magic/scripts/magic.js`).
Свой движок правил не пишем - наш слой только помогает выбрать цель: `addons/magic/scripts/targeting.js` разбирает строки
`range`/`target`/`duration` в ярды и вид цели (себя / касание / дальность / площадь), считает дистанцию до токенов
(`canvas.grid.measurePath`, запасной путь - евклид по клеткам) и ставит таргет через `token.setTarget`.
Обмен с `magic.js` - через глобал `__PD_MAGIC_TARGETING__`: в Foundry это отдельные ES-модули без общей области видимости.

- Строки дальностей сверены с живым миром (1056 заклинаний, 272 молитвы) - см. тесты в `magicchk.mjs`.
  Нераспознанное по-прежнему `kind: "none"`, а не ноль ярдов.
  Сверить поможет `tools/diagnose-magic.js` - печатает форму молитв и заклинаний, уникальные строки
  range/target/duration/damage из компендиумов, сырое против вычисленного и ключи объекта теста. Ничего не меняет.
  Прав ГМ не требует: у Михаила доступ игрока, поэтому запуск - через консоль браузера (F12), вставить файл,
  затем `copy(__pdDump)`. Видно только своего персонажа и открытые игроку компендиумы.
### Проверено на живом мире (Foundry 14.369, система 9.6.3, доступ игрока)

**Структура магии** - догадки заменены фактами:
`target: { value, aoe }` (площадь задана ФЛАГОМ, не строкой), `overcast: { enabled, label, valuePerOvercast, initial }`,
`ingredients: []` (массив, не одно поле), `magicMissile: { value }`, `ritual`, `cn: { value, SL }`,
`range: { value, vortex }`, `duration: { value, extendable }`, `damage: { value, dice }`.
Осторожно: у заклинания без урона `damage = { value: "", dice: "" }` - искать урон можно только по скалярным путям,
иначе вернётся сам объект вместо «урона нет».

**Геттеры системы: работают только у предмета С ВЛАДЕЛЬЦЕМ.** Проверено на обоих случаях:
- свой предмет: «Bolt» с `range.value = "Willpower yards"` отдал `Range = "40 yards"` - УЖЕ ПОСЧИТАННУЮ СТРОКУ,
  а `damage.value = "4"` отдал `Damage = 8` (числом, магический снаряд добавил бонус). Брать надо это.
- предмет из компендиума (владельца нет): `Range = 0`, `Duration = 0`, `Damage = 0` - это «не посчитано», а не ноль.
`preferComputed` принимает и число (>0), и непустую строку, иначе читает сырое поле - оба случая закреплены тестами
(«Молния» и «Касание без владельца» в моке). Ошибиться тут легко: наш разбор по сырой строке дал бы 52 вместо 40,
потому что он берёт характеристику персонажа, а система считает по своим правилам школы.
У ОРУЖИЯ так же: `Damage` = 10 при `damage.value = "SB+5"`.

**Перекаст - одна шкала со своим ярлыком, а не набор категорий.** Включён у 122 заклинаний.
`valuePerOvercast.type` бывает только `value`, `SL`, `characteristic` - это ИСТОЧНИК величины.
Что именно растёт, написано в `label` свободным текстом: «Targets», «Distance (yds.)», «Test Penalty»,
«Fortune Points», «Entangled», «Skeletons»... Значит фиксированных кнопок (урон/цели/длительность) быть не может -
у каждого заклинания своя одна шкала, её и показываем по `label`.

**Дальности** сверены с живым миром (1056 заклинаний, 272 молитвы). Кроме «Willpower Bonus yards» встречаются
«Willpower yards» (всё значение, не бонус), «Half Willpower yards», «Willpower / 2 yards», «2 * Fellowship Bonus yards»,
«Fellowship Bonus miles» (МИЛИ), «1 mile», «20 yards (can't be extended)», «FellowshipBonus yards» (слитно), «You or Touch».
Особые - «Line of sight», «Special», «See text», «Random Vortex» - числа не получают (`kind: "none"`, `special: true`).
Все формы закреплены тестами в `tools/qa/magicchk.mjs`.

**Броня цели** (подтверждено): `status.armour.<локация>.value` - именно то, что читает «урон по цели».
Рядом лежат `layers[]` с флагами `impenetrable`/`partial`/`weakpoints`/`metal` и отдельные `shield`/`shieldDamage` -
пригодятся, если понадобится учитывать качества брони. Есть и `details.size.value` («avg», «sml») -
размер цели влияет на попадание по правилам, сейчас мы его НЕ учитываем.

**Эффект благословения** (из «Blessing of Hardiness»): `changes` меняют `system.characteristics.t.modifier` +10,
`transferData.type: "target"` - эффект уходит НА ЦЕЛЬ, `transfer: false`. Длительность лежит не в эффекте,
а в самой молитве (`duration.value = "6 Rounds"`).

**Прочее с живого мира:** благословения и чудеса НЕСУТ свои ActiveEffect (`transfer: false`) - значит бафф после каста
вешает система, наш мок этого не делает. У актёра есть `addCondition`, `removeCondition`, `applyDamage`, `applyEffect`,
`setupWeapon`. Состояний в конфиге пятнадцать (добавился `defeated`). В компендиумах: мутаций 391, травм 27,
болезней 31, критов 109 - меню «+» в окне группы будет непустым.
`canvas.grid.measureDistance` в Foundry 14 больше НЕТ, только `measurePath`; единица сцены у Михаила = 2, не 1.

Площадь: в `target` у неё стоит РАДИУС («AoE (4 yards)»), а не число целей - у площадных `count: null` и `areaRadius`.

- В моке есть сцена: `MOCK_TOKENS` в `tools/mock-data.mjs`, жрица «Сестра Эльза» с благословениями и маг
  «Магистр Альбрехт» с заклинаниями разных типов, включая случаи с живого мира (нулевые геттеры, мили, особые дальности).
  Токены попадают в мок только при `--cast`.
- Диагностика: `tools/diagnose-magic.js` (магия) и `tools/diagnose-2.js` (эффекты, перекаст, оружие, цель, состояния).
  Обе только читают, прав ГМ не требуют, запуск из консоли браузера.

## Правки от Михаила после игры в живом Foundry (СДЕЛАНО 21.10.2026)

Замечания с реальной сессии. Все пункты ниже исправлены, список оставлен как история решений.

### Окно группы (ГМ)

- **Переключатель состава** - СДЕЛАНО: `GroupApp.scope` = `all` / `online` / `status`, кнопки в шапке рядом с видом.
  В режиме `status` у имени точка «в сети / не в сети» (`.pd-group-dot`), в остальных её нет - лишний шум.
- **Адаптивность** - СДЕЛАНО: `@media (max-width: 720px)` - шапка в два ряда, карточки в один столбец,
  таблица ужимается до 4 колонок (деньги и эффекты прячутся, они есть в карточках).
- **Размер карточек** - СДЕЛАНО: настройка `groupCardSize` (`s`/`m`/`l`), класс `size-*` на сетке карточек.
- **Множественные состояния** - СДЕЛАНО: в меню «+» поле «×N», `addConditionTo(actor, key, count)`.
  Системный `addCondition` зовём N раз: принимает ли он количество вторым аргументом - не проверено,
  а так результат одинаков в любом случае.

### Меню покупки талантов уезжает за край окна

Выпадающий список талантов (`.pd-talentmenu`, `styles/paperdoll.css:2558`) позиционируется жёстко:
`position: absolute; top: calc(100% + 4px); left: 0; right: 0; max-height: 360px`.
Он всегда раскрывается ВНИЗ и наружу окна не выходит - значит при нехватке места снизу уезжает
за нижний край окна снаряжения и его не видно (само окно прокрутку наружу не даёт).

СДЕЛАНО: общий помощник `fitDropdown(menu)` в ядре (экспортирован в `PD_UTIL`) - считает место сверху и снизу,
при нехватке добавляет класс `is-up` (раскрытие вверх) и ставит `max-height` по реальному остатку.
Подключён к меню талантов, отдыха, сортировки и второй полосы.
ВАЖНО: у меню талантов класс `is-open` ставит ещё и шаблон (`offersOpen`), поэтому вызывать нужно
в `onRender`, а не только по клику - иначе перерисовка возвращает меню к раскрытию вниз.

### Расчёты в подсказке оружия - НЕ УЧИТЫВАЕТСЯ

Всё это влияет на «Шанс по цели» и «Урон по цели», которые делает `targetedAttack` в ядре.

- **Кулаки** - СДЕЛАНО: добавлен `_unarmedTarget()` (навык Brawling, без него - ББ) и строка «Шанс попасть»
  в `_unarmedHint`. Причина была в том, что `_attackTarget` требует предмет, а у кулаков его нет.
- **Окружение** - СДЕЛАНО как показ: в строке «Система учтёт» появляется «в бою с N», если рядом больше одного.
  Сам модификатор не считаем - система знает это как «Engaged».
- **Размер цели** - СДЕЛАНО как показ: «цель крупная» в строке «Система учтёт» (из `details.size.value`).
  Складывать нельзя: в живом окне броска система сама подставила +20.
- **Advantage** - СДЕЛАНО как показ: «преимущество N» в строке «Система учтёт».
  В бросок не добавляем - у системы для него отдельное поле в окне.

### ОТВЕТ ПОЛУЧЕН: систему модификаторов считает САМА (снято с окна броска, 21.10.2026)

Заглянули в живой `WeaponDialog` («Weapon Test - Flail», цель - огр, размер `lrg`, преимущество 1):

```
advantage: 1          <- ОТДЕЛЬНОЕ поле, система ведёт его сама
modifier: 20          <- система УЖЕ подставила (+20; цель крупная и/или рывок)
slBonus: 0   successBonus: 0   difficulty: "challenging" (+0)
charging: on
Dialog Modifiers: • Engaged • Melee on a Round when you Charge • ...
```

ИЗМЕРЕНО ДВУМЯ ПРОГОНАМИ (одинаковая обстановка, разные цели):

| цель | размер | `modifier` |
|---|---|---|
| огр | `lrg` | 20 |
| Kidnappers | `avg` | 10 |

Отсюда раскладка: **крупная цель = +10**, **рывок (Charging) = +10** (галка была включена в обоих прогонах),
**преимущество система держит отдельным полем** и в `modifier` не кладёт.
Числа брать из этой таблицы можно только для `lrg` против `avg` - другие размеры не измеряли, не выдумывать.

Выводы, которые меняют план:

1. **Складывать свои модификаторы НЕЛЬЗЯ.** Преимущество у системы в отдельном поле, размер цели и рывок
   уже лежат в `modifier`, про «Engaged» она тоже знает. Если мы добавим то же самое - удвоится.
2. **Наш «+20 за стрельбу в упор» под подозрением.** Он складывается в «Шанс по цели», а система,
   судя по всему, считает полосу дальности сама. Нужно проверить тем же способом на СТРЕЛКОВОМ оружии:
   открыть окно броска из лука/пращи по дальней цели и посмотреть, что в `modifier`.
3. **Правильная цель для нашей подсказки** - не считать, а ПОКАЗЫВАТЬ. То есть выводить базовый шанс плюс
   справочные строки («цель крупная», «ты в окружении», «преимущество 1», «в упор»), не складывая их в число.
   Либо читать `modifier` у системы, но это требует открытия диалога - для подсказки слишком тяжело.
4. Пункты списка выше про окружение, размер и преимущество из «посчитать» превращаются в «показать».

Данные для справки: у цели размер в `details.size.value` (`avg`, `lrg`, `sml`), преимущество - в
`system.status.advantage.value`, «кто рядом» считается по токенам (у нас уже есть `tokensInRange`).
